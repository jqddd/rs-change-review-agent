# 遥感变化复核工具接入约定

版本：v0.1（待两位开发者共同确认）  
适用项目：rs-change-review-agent  
建议仓库位置：docs/tool-contract.md

## 1. 目的与范围

本项目基于 Change-Agent 所带的 Lagent 框架扩展遥感变化复核工具。第一版复用已有框架，不重新实现 Agent、工具执行器或状态码体系。

新增算法采用独立工具方式接入：继承 `BaseAction`，通过 `run()` 或 `@tool_api` 暴露方法，并将工具实例加入 `ActionExecutor`。不通过扩充 Python Interpreter 提示词接入新算法。正式有限工具调度入口不同时开放通用 Python Interpreter；原入口可以保留用于对照。

本约定规定工具如何接入及数据如何衔接，不预先指定配准、质量检查或备用变化检测的具体算法。算法须先调研、验证，再接入。

## 2. 复用原框架

- 工具基类：`lagent.actions.base_action.BaseAction`。
- 多方法工具：使用该模块的 `tool_api` 装饰器。
- 执行与启用：`lagent.actions.action_executor.ActionExecutor`。
- 执行结果与状态：`lagent.schema.ActionReturn`、`ActionStatusCode`。
- 参数解析：沿用默认 `JsonParser`，工具调用参数使用 JSON 对象。

单功能工具优先定义 `run()`；一组紧密相关的方法可使用 `@tool_api`，由框架以“工具名.方法名”暴露。工具名必须唯一。

工具须被导入、实例化，并加入当前 Agent 的 `ActionExecutor(actions=[...])` 才算启用。仅添加文件或进入类注册表，不代表当前 Agent 可以调用。

当前项目的 `JsonParser` 主要检查参数名称和必填项，不能替代完整类型、取值范围和文件内容校验。上述校验由工具适配层负责。其非 JSON 回退行为服务于原 Interpreter；新独立工具按合法 JSON 验证，不依赖该回退。

## 3. 算法实现与工具适配分离

每个工具分为两部分：

1. 算法实现：负责模型加载、预处理、推理或几何计算，能够脱离 Lagent 单独调用。
2. 工具适配：负责参数检查、调用算法、整理文件引用与诊断信息、返回框架结果。

已有 MCI 的 `Change_Perception` 可以复用，无须重写网络。适配时检查输入限制及输出含义，不把演示入口直接视为通用数据接口。

模型路径、设备、权重版本及固定配置由程序配置或工具构造参数管理，通常不作为 LLM 可任意更改的参数。模型加载策略必须明确，避免每次调用不必要地重复加载。

双方各自维护自己的算法与适配文件。公共注册入口、共享数据结构及 Agent 核心文件的修改须提前协调。具体目录沿用团队现有布局，不另建重复框架。

## 4. 输入与参数

- 第一版使用本机文件路径传递影像和 Mask；对外返回绝对路径，避免依赖当前工作目录。
- 双时相输入统一命名为 `image_before`（T1）、`image_after`（T2）。不交换时序。
- 需要生成文件时使用 `output_dir` 指定允许的输出目录，并为每次执行建立独立结果位置，避免覆盖其他任务。
- 不同算法可以有不同参数；同一含义使用相同名称，不要求所有工具拥有相同签名。
- 为参数提供类型标注、清楚的 Args 文档，以及默认值和允许范围。
- 调用前检查文件存在性、通道、尺寸、有效区域及算法必需的条件。不支持的输入明确拒绝，不能悄悄转换后不记录。
- 不修改原始输入文件。缩放、裁剪、配准或增强后保存新文件，并记录处理关系。
- 不向 LLM 传输大数组、影像张量或模型权重；传递文件引用和必要的摘要。算法内部可使用数组。

## 5. 遥感数据含义

### 5.1 图像与坐标

每个输出说明尺寸及参照坐标。无地理信息的 PNG 使用像素坐标，原点在左上角，x 向右、y 向下。

若返回矩形区域，统一使用 `[x_min, y_min, x_max, y_max]`，右边界和下边界不包含在区域内；说明区域属于哪张影像。

配准工具声明参考影像、待变换影像和输出所在网格。优先以 T1 为参考，将 T2 对齐到 T1；不同策略须明确说明。返回变换信息或其文件引用，并记录无效边缘。局部工具返回裁剪位置与回填关系。

GeoTIFF 等地理数据保留或明确记录 CRS、像素大小、地理变换和 NoData。缺少可靠地理信息时，只报告像素面积，不伪造平方米。评测时预测与标注须位于同一网格和有效区域。

### 5.2 Mask

用于计算的 Mask 保存为单通道整数标签文件；彩色可视化另存。返回标签字典，不能只交付彩色图片。

MCI 当前标签为 `0=未变化、1=道路变化、2=建筑变化`。二值建筑变化模型可以采用 `0=未变化、1=建筑变化`，但必须声明其编码；不同编码不能直接做统计或比较。

不同模型比较前，需要明确类别映射、空间对齐和有效区域。LEVIR-MCI 与 LEVIR-CD 的数据及标签口径不可直接混用。二值变化不自动等同于“新增”或“拆除”。

连通域计数报告为“变化连通区域数”，记录连通性和面积过滤阈值，不默认等同于真实建筑栋数。

## 6. 返回结果

执行状态沿用 `ActionReturn.state`，不另造一套重复状态码：

- `SUCCESS`：工具正常完成计算。
- `ARGS_ERROR`：参数或输入条件不满足。
- `API_ERROR`：算法加载、推理、计算或输出失败。
- HTTP 服务调用错误可使用原框架的 `HTTP_ERROR`。

失败填写 `errmsg`，包含可定位的原因，不包含密钥。文件写入必须检查是否成功。不能只返回带有“失败”文字的普通字典，否则框架可能仍将其标记为成功。

成功计算不意味着结果可信。例如配准检查正常运行后发现严重错位，应返回 `SUCCESS`，并在诊断信息中报告问题；不能把该检查结果当作程序故障。

为统一结果内容，新增工具的成功结果使用可 JSON 序列化的字典，至少包含：

- `schema_version`：第一版为 `0.1`。
- `run_id`：本次执行的唯一标识。
- `summary`：简短事实摘要，不编造诊断结论。
- `artifacts`：输出文件列表；每项包含 `kind`、`path` 及该数据必要的元信息。没有文件输出时为空列表。
- `diagnostics`：算法实际提供的诊断指标、单位和解释；无诊断信息时为空对象。
- `warnings`：可信边界、适用条件或其他警告；没有则为空列表。
- `elapsed_seconds`：本次工具调用耗时，说明是否包含首次加载；GPU 计时须确保计算已完成。
- `provenance`：算法名称、版本、权重标识、实际配置及输入引用。没有权重的算法明确注明不适用。

算法特有结果可增加字段，但不能改变已有字段的含义。不要为了填满字段虚构置信度；模型概率也不直接当作经过校准的可信度。

本仓库的默认解析器会把返回字典序列化为 JSON 文本，包装为 `ActionReturn.result` 中的文本项。LLM 实际收到的是该文本。可直接返回成功字典交由框架包装；需要明确失败状态时返回 `ActionReturn`。适配层可将同一结果字典保存为运行记录，供程序和评估读取。

## 7. 工具说明与 Agent 职责

每个工具的文档说明：功能、适用条件、输入、输出、限制及主要成本。明确区分观察事实、算法估计和建议行动。

工具负责检查或计算，Agent 决定下一步调用哪个工具。第一版不在一个工具内部隐式运行整个复核工作流；确有组合算法时，说明实际执行步骤和总成本。

重试上限、预算及允许行动由程序执行约束，不能只靠提示词。使用原 ReAct 循环上限不代表已经实现配准重试次数等场景约束；这部分由公共调度模块另行实现。

真实测试标注只交给独立评估程序，不作为 Agent 选择工具的证据。扰动参数可以用于构造和评测，不默认作为实际部署可获取的诊断信息提供给 Agent。

## 8. 环境与依赖

复用已验证环境，新增依赖先独立验证并记录。未经协调，不升级公共环境的 PyTorch、CUDA 相关包或 Lagent 依赖。

冲突严重的算法可以使用独立环境，通过子进程或服务适配，但对外仍遵循同一工具契约，报告启动和执行成本。

不提交 API Key、环境目录、临时缓存、私有数据或新下载的大型权重。保留第三方代码的许可证与来源，提供数据和权重获取说明。不为清理文件而擅自重写已有 Git 历史。

## 9. 每个工具的完成标准

1. 算法脱离 Agent 能运行，输入输出含义明确。
2. 工具按合法 JSON 参数调用成功，返回符合约定。
3. 至少验证一个正常输入和一个无效输入；诊断工具还需验证对应异常场景。
4. Agent 可按明确指令调用，日志能证明实际执行。
5. 与已有工具组合时，路径、类别和坐标正确衔接。
6. 附环境、权重来源、调用示例、限制及验证结果。
7. 另一位开发者按说明验证通过。

按指令调用成功只证明接入完成，不证明自主调度有效。自适应选择、成本收益及规则基线比较属于后续场景验收。

## 10. 两人协作与变更

两人确认本约定及共同基线提交后，分别建立功能分支开发。每个工具有一个明确负责人，另一人审查。可以使用 AI 编写代码，但须让 AI 先读取本约定和原项目接口，并由负责人验证结果。

原 Change-Agent 的 MCI 与框架优先复用。当前任务是补充独立工具适配，而非重复实现已有网络或重新训练。

接口变化通过 PR 说明原因、影响的工具及调用方，并同步修改文档和验证。新增可选字段尽量兼容旧接口；破坏性变化更新契约版本，不单方面修改。

框架以后可以替换或调整。算法实现保持独立，迁移优先修改适配层；不承诺更换框架完全零修改。

未来团队若提供统一的 RasterAsset、MaskAsset、EvidenceCard、ToolRun 等契约，以共同确认后的团队标准为准，集中适配，不各自维护不兼容格式。
