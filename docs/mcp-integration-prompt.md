# 场景 C · 模块完成后的 MCP 接入提示词

## 新窗口怎么用

等模块的 Python 功能已跑通、输入输出基本稳定后，把下面这句话发给 Codex。只需替换模块名、功能和交付范围。本文是未来任务模板；当前轮用户明确指定的范围优先。

> 请读取 `docs/mcp-integration-prompt.md` 并执行。目标是模块 7「统计与解释」中已有的建筑变化统计功能。交付范围：本地部署和验证，通过后向对应模块分支提 PR 并合入该模块分支。请边做边教我。

以后如果新增模块 8，把示例中的模块名和功能换成届时确定的定义。若只想本地试跑，交付范围填“仅本地实现和验证”。

## 给 Codex 的执行提示词

你和我共同维护团队仓库 `jqddd/rs-change-review-agent`。请将我本轮点名的、已经实现的模块能力封装为可复现的本地 stdio MCP 服务。按下面的顺序执行，并让我能在自己的 PowerShell 复现。

1. **先找到真正的实现。** 阅读仓库中的 [工具契约](tool-contract.md) 和 [能力画像](capability-profile.md)，如有对应模块方案也一并阅读，结合本轮目标核对 GitHub 上对应的模块分支、PR、依赖和本地工作区。展示现有 Python 入口、输入、输出及一组可运行样例。如果某项业务能力尚未实现，指出缺口，不要用模拟结果代替。
2. **确定 Agent 要调用的动作。** 用一句用户能提出的问题解释每个工具的用途，说明它接哪个上游、给哪个下游提供什么。同一服务可以暴露多个独立动作。说明哪些函数只在工具内部调用。保持已有语义，例如三分类标签、有效区、单位和拒绝处理状态。
3. **实现薄封装。** 使用 Anthropic 官方 `mcp-builder` skill 和[已验证的 TinyCD MCP 示例](https://github.com/jqddd/rs-change-review-agent/tree/feat/tinycd-tool/algorithms/tinycd/mcp_demo)。复用原算法入口，建立独立 uv 项目、锁文件和 stdio 服务。只暴露推理或处理功能。工具说明写明输入限制、输出字段、文件读写位置和失败条件。路径在服务端解析；项目内路径从代码位置推导，示例使用队友可取得的数据。算法涉及权重时说明来源和放置位置；经典图像处理记录库版本与参数。
4. **先测业务，再测协议。** 在按锁文件建立的环境中列出工具和输入输出字段；用同一真实样例分别执行直接 Python 调用和 MCP 调用。图像核对像素，统计核对数值、单位和分母，描述核对实际文本或适用的判定标准。再验证一个有意义的异常或边界输入。演示生成的路径每次可不同，验证应比较内容。模型精度如需评估，另与标注比较。
5. **给队友写可复制的 README。** 写清代码、样例和权重从哪来，如何 `uv sync --locked`、发现工具、调用它、打开结果，以及应该看到什么。列出 MCP 客户端启动服务所需的解释器和参数，并分别记录本地部署、样例验证、Agent 自主调度的实际完成状态。
6. **按本轮授权交付。** 若要求发布，从远程实际包含业务代码的模块分支开独立工作目录，只提交所需源码、环境声明、锁文件和复现说明。检查差异后推送功能分支，向对应模块分支提 PR；仅在本轮要求合并且测试通过时合入，核对远程状态。团队的公共基线 PR 留给团队评审。`exp/merge-all` 只留本地。若没有对应模块分支，先说明可用基线和拟议目标。不要提交虚拟环境、权重、运行输出或个人绝对路径。
7. **边做边讲。** 每步用两三句话说明“这一步在检查什么、为什么做、看到什么算成功”。结束时给我一条亲手发现工具的命令、一条真实调用命令，并报告样例结果、未验证项和已授权创建的 PR。

## 模块 7 的验收例子

若已有建筑 Mask 统计函数，先用 TinyCD 的全有效 `test_77` 标签 PNG 验证：尺寸 256×256、建筑变化像素 11916、有效像素 65536，占比约 18.18%。统计结果应来自实际读取文件。若输入 MCI 三分类标签，建筑为 2、道路为 1；若另有有效区掩膜，分子和分母都只计有效像素。计算平方米还需要可靠的单像素地面面积。这个例子用于明确接口和验收口径，不能替代未来模块的实际定义。
