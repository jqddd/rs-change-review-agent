# 算法内置预处理核验（场景C · 6 个变化检测算法）

> 回答一个问题：**把两张原始遥感图直接塞进算法，算法内部到底做了哪些预处理？哪些没做？**
> 结论一句话：6 个算法都**只做「把图塞进网络」所必需的最小预处理**（RGB 转换、按需 256 缩放、各自归一化常量），**没有任何一个内置配准、质量检查、去噪、去模糊、亮度/辐射校正、裁剪/有效区**。
> 这些「外部预处理」在工具层被声明为**调用方前置条件**，不是算法内部完成。

---

## 1. 结论摘要

| 预处理能力 | 谁做了 |
|-----------|--------|
| RGB 转换 / 剥离 alpha | ChangeFormer、BIT、TinyCD（`.convert("RGB")`）；SNUNet、DDPM-CD（强制校验 RGB） |
| 缩放到 256×256 | MCI、ChangeFormer、BIT、TinyCD（仅当输入非 256 才缩放）；SNUNet、DDPM-CD **不缩放、强制 256** |
| 归一化（减均值/除方差） | 全部有，但**常量各不相同**（见第 3 节） |
| 配准 / 几何对齐 | **全部没有** |
| 质量检查（清晰度/云量/阴影/坏像素） | **全部没有** |
| 去噪 | **全部没有** |
| 去模糊 | **全部没有** |
| 亮度/辐射校正、直方图匹配 | **全部没有** |
| 裁剪/有效区/有效像素 mask | **全部没有** |

**结论**：week1「直接丢原图结果看着挺准」，是因为 LEVIR 测试图本就**干净、对齐、256×256**。真实遥感图（光照/季节差异、几何偏移、噪声、模糊）不会满足这些隐含前置条件——这正是队友补「质量检查/错位/配准」工具、以及需要单独做「预处理/修复」模块（模块4）的原因。

## 2. 逐算法预处理清单

### 2.1 MCI（`Multi_change/predict.py`，三分类+描述）
- **归一化**（96-97 行）：`mean=[0.39073·255, 0.38623·255, 0.32989·255]`≈`[99.64, 98.49, 84.12]`，`std=[0.15329·255, 0.14628·255, 0.13648·255]`≈`[39.09, 37.30, 34.80]`（LEVIR-MCI 数据集统计，0–255 尺度）。
- **resize**（141-143 行）：仅当非 256 才 `cv2.resize` 到 256，**但发生在 `transpose(2,0,1)` 之后的 CHW 数组上**，且**先归一化后 resize**——两处都是问题（见 bug ①）。
- **通道**（128-134 行）：`imageio` 读 RGB，`transpose(2,0,1)` 硬性假定 3 通道，不读 alpha、不转灰度。
- **设备**：**硬编码 `.cuda()`**，无 CPU 回退（见 bug ①）。
- **外部预处理**：无。

### 2.2 ChangeFormer（`algorithms/changeformer/inference.py`，二值）
- **归一化**（26-27 行）：`[0.5,0.5,0.5]/[0.5,0.5,0.5]`（[0,1]→[-1,1]）。
- **resize**（45-46 行）：非 256 才 BICUBIC→256。
- **通道**（44 行）：`.convert("RGB")`，剥 alpha。
- **设备**（35 行）：cuda→cpu 自动回退。
- **外部预处理**：无。

### 2.3 BIT（`algorithms/bit/inference.py`，二值）
- 同 ChangeFormer：`[0.5,0.5,0.5]/[0.5,0.5,0.5]`，非 256 才 BICUBIC，`.convert("RGB")`，cuda/cpu 自动回退，无外部预处理。

### 2.4 TinyCD（`algorithms/tinycd/inference.py`，二值）
- **归一化**（25-26 行）：ImageNet `[0.485,0.456,0.406]/[0.229,0.224,0.225]`。
- **resize**（45-46 行）：非 256 才 BICUBIC。
- **通道**（44 行）：`.convert("RGB")`。
- **设备**（34 行）：cuda/cpu 自动回退。
- **外部预处理**：无。

### 2.5 SNUNet-CD（`algorithms/snunet/inference.py`，二值，双 profile）
- levir_c16 在 PIL RGB 上使用 ImageNet RGB 均值与标准差；cdd_c32 不归一化。
- **resize**：**不缩放**，`validate_image`（67-83 行）强制要求正好 RGB 256×256，否则抛错拒绝。
- **通道**：严格 RGB 256×256，只收 PNG/JPEG。
- **设备**（97-101 行）：请求 cuda 但不可用会**直接抛错**，不自动回退。
- **外部预处理**：无（`validate_image` 只是格式/尺寸契约校验，不是质量/辐射/几何检查）。

### 2.6 DDPM-CD（`algorithms/ddpm_cd/inference.py`，二值）
- **归一化**（133 行）：`(x/255)·2−1` → [-1,1]，无逐通道 mean/std。
- **resize**：**不缩放**，`validate_image`（29-42 行）强制 RGB 256×256 PNG/JPEG，否则拒绝。
- **设备**（102-106 行）：cuda 不可用直接抛错，不回退。
- **外部预处理**：无（仅格式/尺寸契约校验）。

## 3. 归一化常量对比（这是各算法互不兼容的关键点）

| 算法 | mean | std | 尺度 |
|------|------|-----|------|
| MCI | [99.64, 98.49, 84.12] | [39.09, 37.30, 34.80] | 0–255 |
| ChangeFormer | [0.5, 0.5, 0.5] | [0.5, 0.5, 0.5] | 0–1 → [-1,1] |
| BIT | [0.5, 0.5, 0.5] | [0.5, 0.5, 0.5] | 0–1 → [-1,1] |
| TinyCD | [0.485, 0.456, 0.406] | [0.229, 0.224, 0.225] | 0–1 |
| SNUNet(levir) | [123.675, 116.28, 103.53] | [58.395, 57.12, 57.375] | 0–255（RGB 序） |
| SNUNet(cdd) | 无 | 无 | 0–255 |
| DDPM-CD | (x/255)·2−1，无逐通道 | 无 | 0–255 → [-1,1] |

> 归一化各自在算法内部完成，**调用方不需要（也不应该）再归一化**。这意味着：如果模块4 的预处理工具要在「检测之前」改图像，必须保证**不破坏各算法期望的输入尺度**（例如统一输出 0–255 uint8 RGB，让算法内部自己去归一化）。这是模块4 与模块5 衔接的关键约束。

## 4. MCI 的设备与尺寸限制

### bug ① MCI 硬编码 `.cuda()` + resize 作用于 CHW（`Multi_change/predict.py`）
- `__init__`（119-123 行）对 encoder/encoder_trans/decoder 直接 `.cuda()`；`generate_change_caption`（156-157 行）、`change_detection`（175-176 行）对输入张量直接 `.cuda()`，**全无 CPU 回退**。
- `preprocess`（126-150 行）先归一化（135-139 行）再 `cv2.resize`（141-143 行），且 resize 作用在 `transpose(2,0,1)` 之后的 CHW 数组上——`cv2.resize` 期望 HWC 或 2D，传 CHW 语义错误。
- **影响**：无 GPU 环境跑不动（违反 MCP 文档「CPU+GPU 双支持」）；输入非 256 时触发 resize bug（当前 LEVIR 样例都是 256，未触发）。
- **建议**：把 `.cuda()` 改为按 `torch.cuda.is_available()` 参数化；把 resize 移到归一化之前、且在 HWC 上做，或直接强制输入 256 像 SNUNet 那样拒绝非 256。

## 5. 对模块划分的启示

1. **模块1（数据与坐标处理）/ 模块4（预处理修复）必须独立存在**：算法层不负责配准、质检、去噪、去模糊、亮度校正，这些只能由工具层补。
2. **「检查→修复」链条成立**：队友的模块2（质量检查）/模块3（错位配准）负责「发现问题」，模块4 负责「尝试修复」。
3. **模块4 的输出必须保持「0–255 uint8 RGB 256×256」**，否则与模块5（检测器）的隐含契约冲突（尤其 SNUNet/DDPM 强制 256 且不缩放）。
4. 归一化是算法内部职责，模块4 的预处理工具**不做归一化**，只做「让两期影像更可比」的几何/辐射/降质修复。

## 6. 模块4 实测结论（重要，负面结果）

用 week1 的三个 LEVIR 样例，对比「ChangeFormer 直接检测」vs「先 `histogram_match`(T2→T1) 再检测」：

| 样例 | \|T1-T2\| | ChangeFormer F1 处理前 → 处理后 |
|------|-----------|--------------------------------|
| test_77（难，光照噪声） | 62.6 → 59.9 | 0.757 → **0.686** |
| test_121（难，变化弱于噪声） | 35.8 → 26.1 | 0.856 → **0.845** |
| test_102（简单例） | 58.0 → 25.9 | 0.987 → **0.122** |

在此处三组样例上，直方图匹配后 ChangeFormer F1 均下降，实验尚未区分具体原因。
